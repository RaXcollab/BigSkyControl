BigSky YAG Laser — BLACS Integration via ZMQ

Date: 2026-02-21  |  Author: Arian Jadbabaie (with Claude Code)  |  Commit: e6b3acf  |  Project: BigSkyControl

Summary

Added a ZMQ server to the BigSky YAG laser control hub (HugeSkyController.pyw) enabling full remote control from BLACS (labscript-suite experiment control system). BLACS can now set voltage, open/close the shutter, activate/deactivate lamps, arm/disarm the Q-switch, change trigger modes, start warmup, stop the laser, and read status parameters (temperature, voltage, lamps, shutter, Q-switch) — all via the standard ZMQ REQ-REP + PUB-SUB protocol defined in the BLACS Communication Contract.

Architecture

Thread Safety Model

The ZMQ server runs in a daemon thread inside HugeSkyController.pyw. All serial I/O to the BigSky laser must happen on the Qt main thread. The cross-thread bridge works as follows:

  1. ZMQ thread receives a PROGRAM_VALUE request from BLACS
  2. ZMQ thread creates a concurrent.futures.Future and calls ctrl.executeRemoteCommand(param, value, future)
  3. executeRemoteCommand emits a pyqtSignal (auto-queued to the main thread)
  4. Qt main thread slot _handleRemoteCommand dispatches to the appropriate handler, does serial I/O, collects the handler's {"status", "message"} dict, and writes it to the future via future.set_result(...) in finally
  5. ZMQ thread reads the dict via future.result(timeout=10.0) and forwards it directly as the REP response. A concurrent.futures.TimeoutError is mapped to a generic timeout-error reply. Rejection paths (e.g. mode change while laser is firing) propagate as {"status": "ERROR", "message": "rejected: ..."} instead of the previous silent SUCCESS

Shared state (fLampVoltage, lastTemperature, activeStatus, shutterStatus, qSwitchStatus) is protected by a threading.Lock (_stateLock) and exposed via thread-safe getters used by the ZMQ thread for CHECK_VALUE and PUB-SUB broadcasts.

Typical Triggered Mode Workflow

Standard externally-triggered configuration: Q-switch mode = internal (0), Flashlamp mode = external (1). The external trigger (5V, 100μs pulse on Pin 4/Pin 9) fires the flashlamps; the Q-switch fires internally with each lamp pulse.

Typical BLACS transition_to_buffered sequence:

  1. YAG_1_stop = 1 — ensure standby (mode changes require standby)
  2. YAG_1_qswitch_mode = 0 — internal Q-switch
  3. YAG_1_lamp_mode = 1 — external flashlamp trigger
  4. YAG_1_voltage = (desired V) — set flashlamp voltage
  5. YAG_1_lamps = 1 — activate lamps
  6. YAG_1_shutter = 1 — open shutter
  7. YAG_1_qswitch = 1 — arm Q-switch
  8. Laser is now ready to fire on external trigger pulses

Safety Rules (Enforced by ZMQ Handlers)

  • shutter=1 requires lamps active → returns ERROR if lamps not active
  • qswitch=1 requires lamps AND shutter active → returns ERROR if not
  • lamp_mode / qswitch_mode require standby (lamps off) → returns ERROR if active
  • lamps=0 (standby) also clears shutter and Q-switch state
  • Voltage range validated: 500–1400V → returns ERROR if out of range

Testing

All tests passed in dummy mode (no physical laser connected).
  • HELLO: Server responds with {"status": "SUCCESS"}
  • CHECK_VALUE: All 5 monitors return correct values (temperature_monitor, voltage_monitor, lamps_monitor, shutter_monitor, qswitch_monitor)
  • PROGRAM_VALUE: Voltage setting, lamp activation, shutter open, and stop all execute correctly
  • Error handling: Unknown connection names return {"status": "ERROR"} with descriptive messages
  • PUB-SUB: All monitor topics broadcast at ~4 Hz, heartbeat at ~1 Hz
